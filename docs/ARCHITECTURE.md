# Architecture

ExcelJS import → normalized free-form containers → indexed global reference lookups → evidence candidates → structured candidate → pure Hybrid candidate generator → fixed priority selector → separate validator → status/review queue → audited Excel export.

Engine A lives in parser/ and enrichment/. It uses ReferenceRepository (reference/types.ts); SqliteReferenceRepository is the initial adapter. Country selection follows configurable authority order, while conflicts block automation. The generic parser recognizes independent locality tails in any field; postal formats and country aliases are data-driven. No universal US street/city/state assumption is made.

Engine B lives in hybrid/. It receives only StructuredAddress and returns candidates, final lines, dropped data and truncation entries. It has no database, country lookup, external network, AI or confidence dependencies. The validator checks the internal slash profile and source semantics separately.

SQLite stores reference data, batches, per-record payloads, versions, and append-only review events. Record updates and review event insertions share a transaction; optimistic version comparisons reject stale decisions. Original source values remain immutable. Review events now capture the authenticated local account ID/username separately from decision initials; legacy events remain unchanged. src/lib/auth.ts centralizes sessions, credentials and per-endpoint role checks, while src/lib/access.ts scopes batch payloads and direct record mutations by immutable source Group. auth_users, auth_sessions, auth_groups, auth_login_attempts and auth_audit are additive SQLite tables.

Next.js Node APIs ingest files, persist results, validate edits and export. Client React handles upload, summary filters, exception queue, evidence, audit, live deterministic edit preview and export. Client previews are advisory; server validation governs approval.

The browser upload flow inspects workbook bytes, persists an expiring draft, maps a selected worksheet, and queues source rows in SQLite. A separate supervised worker commits atomic chunks with lease fencing, cursor recovery and a reference snapshot pin. Incomplete jobs cannot review/export. Reference administration stages separate candidate files, validates them and atomically switches an audited pointer with retained rollback versions. See WORKFLOW_MANAGEMENT_v1.8.md. The legacy direct-file endpoint remains synchronous for compatibility. The 50,000-row/20MB limits remain. A long-running internal Node service is required; the v2 UI uses bounded server-side pages, scoped metadata and a compact derived record index. Reviewer reservations complement optimistic versions. Background exports stream a read snapshot in a registered child process, with private retained artifacts and lease recovery. The legacy complete-batch endpoint remains for integrations. No external providers are enabled. AddressValidationProvider defines a future evidence-only integration boundary.

Acceptance is an independent review decision. Single-record ACCEPT persists the exact proposal and findings; batch acceptance runs in one SQLite transaction over a versioned explicit pending selection. Accepted-output snapshots are stored in review events and exported. Accepted exceptions remain distinct from validation PASS and automatic translation.

The source envelope now contains Group plus typed additionalColumns entries (original header, value, number format and optional original formula/hyperlink). analysisInput explicitly projects the five analyzed fields before Engine A, preventing Group and extras from influencing even normalization notes. SQLite JSON persistence and review retain the complete envelope. Excel export unions extra headers across all records, restores dates and numeric formatting, and namespaces computed header collisions. Group selection/sort helpers are shared by the UI and export API.

ExportMode is shared by UI and server. The server validates mode independently and defaults to full for backward compatibility. Source + Hybrid uses a lightweight projection of source data and stored Hybrid lines and returns before constructing Summary/Audit; it does not serialize the analysis or recompute the transformation. Header collision and typed source-cell handling are shared across formats.

The v1.4 Name interpretation module (parser/name.ts) consumes only Name and Address1 inside the five-field intelligence boundary. An enrichment-supplied indexed locality guard prevents geographic text from being automatically removed as a Name duplicate. Interpretation yields a Name candidate, cleaned source containers, review reasons and a separate action audit. No fixed Hybrid rules were made probabilistic. Name edits pass through the same normalized preview and server-side rules. Legacy records remain readable and are not silently reprocessed.

## v2 derived state and concurrency

record_index and dirty markers preserve the authoritative records payloads. Normal writes update the index in the same transaction; pure SQLite triggers detect legacy writes and support rollback compatibility. The supervisor warms outstanding index entries before serving. Queries read counts, scope, revision and page rows from one snapshot; natural Group sorting retains source-order ties. Short write transactions use BEGIN IMMEDIATE when reading state that they will update, preventing SQLite read-to-write upgrade failures.

record_reservations holds hashed editor tokens and expiring ownership, with explicit Admin release auditing. Version predicates still fence stale saves. export_jobs captures selection and lifecycle; its registered worker child reads one immutable snapshot and writes a private random partial file before atomic publication. Download authorization is rechecked on every request; Group Users cannot queue or download exports. See V2_UPGRADE_AND_OPERATIONS.md for contracts, retention, restart and rollback details.

Group summaries and per-status counts are maintained incrementally with record writes in the same transaction. Common single-status pages and dashboards read these compact totals; multi-status/search intersections retain the indexed unique-record query. Pure SQLite dirty markers allow rebuilding totals after legacy writes/deletes without changing authoritative records.
