Official first-patch packages support v1.10.0, v1.11.0 and v1.11.1. Each signed manifest requires its exact base version and pre-change file hashes. A standalone Node installer in the bootstrap ZIP can install into existing releases without replacing the application folder. Future updates use npm run update. The updater preserves data, environment/local Next configuration, reference archives/databases and samples, creates consistent operational SQLite snapshots and backs up affected code/build outside the app root. It rebuilds in place and runs npm ci only for changed/missing dependencies. Code rollback does not restore/erase the operational database. Runtime leases, a maintenance lock and an operation journal support stopped-host maintenance and interrupted-operation recovery. The first trusted installer/public key establish signature trust; private signing keys are excluded from source and downloads.

The source/full-install ZIP remains available for new installs and release baselines; patches are the primary delivery for existing installations. Source archives exclude .mwtsi runtime state, node_modules, builds, customer databases, .env files, uploads, operational backups and private signing material. Read PATCHING.md for first/future patch commands, supported versions, database/port/environment settings, source conflicts, backup retention, code rollback and interrupted first-update recovery. Destructive or incompatible database migrations are outside this preserve/additive-only patch policy and require a separately reviewed migration procedure.
